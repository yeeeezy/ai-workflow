# FEAT-298 Player window-frame vault

Status: in_progress. Started: 2026-10-17.

## User request and scope

- Let the current playable 3C player cross a window frame with a weapon-lowering/stowing beat and both hands supporting the crossing.
- Reuse one traversal performance across weapons; use small weapon-specific presentation settings only where necessary.
- First investigate existing assets and then implement. FEAT-297 glass-breaking redesign remains planned and deferred; this feature covers traversal through an already open frame only.
- TheManTest is a destination-only animation project. Retarget/source rigs and source skeleton work must happen in TMIIR or FPSShooter1; migrate only final animations.

## Read-only findings

- The playable `AFPSCharacterBase` has a camera-mounted `ArmsViewMesh` and separate body AnimBP. The body copies the first-person upper-body pose. Jump input currently calls `ACharacter::Jump` directly.
- EquipmentManager's `Unequip` is a gameplay lifecycle operation: it unlinks animation layers and revokes weapon abilities. Traversal needs a temporary presentation/ability lock without changing inventory ownership.
- Existing window frame and glass static meshes are in `Content/BlockingStarterPack/Meshes/Architecture/WindowsSet`. No player Vault/Mantle animation is installed in TheManTest.
- TMIIR has UEFN mannequin Vault, Mantle, Hurdle and Catch montages/sequences. `M_Neutral_Traversal_Vault_1_0_stand_F_Lfoot` is a 2.567-second root-motion AnimSequence on `/Game/Characters/UEFN_Mannequin/Meshes/SK_UEFN_Mannequin`; matching AM montage is 2.2 seconds. `RifleAnimsetPro/Animations/InPlace/HolsterRifle` is a 1.8-second sequence on a different UE4 Mannequin skeleton. These are candidates only; contact pose and target skeleton compatibility need validation.
- TMIIR has prior MaintenanceWorker body and first-person meshes/skeleton work. The target's two view meshes and candidate source skeletons still need an authoring audit.

## Work plan

1. Inspect frame dimensions, collision, player skeletons and source action visually/in metadata. Pick the animation and create matching body and first-person final sequences externally, keeping source rigs out of TheManTest.
2. Implement a reusable traversable-window actor/anchor with entry, exit and hand-contact positions. Validate a clear opening and landing region before starting; normal Jump remains the fallback.
3. Add a traversal state that temporarily hides/lowers the equipped weapon and blocks firing/switching, plays synced body and first-person actions, moves the capsule through the opening and restores weapon state on completion or interruption. Do not call regular Unequip solely for presentation.
4. Add focused automated and rendered PIE tests for accepted vault, blocked opening, no-window Jump, weapon lock/restore and both-hand contact presentation. Compile/save assets and update relevant architecture docs.

## Decisions pending visual validation

- The exact Vault vs Mantle sequence and frame geometry depend on previewing their contact frames.
- Use authored animation and window alignment first. Add hand IK/Control Rig only if varying frame dimensions visibly break hand contact. Motion Warping may be useful for root alignment but is not currently enabled in the project descriptor.
